# Vireo evidence and scientific implementation

This package supports the integrated Vireo analysis in manuscript Sections
3.8–3.10 and 4.7–4.9, Tables 6–7, and Figures 6–8. The experimental object is
one public Vireo checkpoint, its neutral-training comparator, and their base.
Multiple prompt sets do not constitute independent model replications.

| Directory | Contents |
|---|---|
| `elicitation` | 14 published and 12 authored development conversations, audit-cue and provider-choice controls, exact responses, rubric, judgments, analyses, and generation code |
| `auditing` | 48 new conversation families, history transplants, full Jacobian/sparse-channel implementation, all 29 conditions, raw responses, blind judgment mappings, both judges, frozen forecasts, and diagnostics |
| `auditing/initial_confirmation` | 32 distinct initial-answer families, the same complete condition roster, initial-context directions, raw records, both judges, and frozen prospective forecasts |
| `neutral_training` | Exact neutral training JSONL, recorded two-stage configurations, and native MLX training/reference code |

`SOURCE_MAP.json` hashes the unmodified scientific inputs imported into this
release. Original protocol text, identifiers, and execution paths are retained
for provenance. In particular, initial-answer contexts were selected after the
shared-neutral-history effect failed the one-point behavioral gate. New prompts
and measurements were then frozen before their outcomes. The manuscript treats
these as conditions of the same scientific investigation without pooling their
samples or representing the entire adaptive design as globally preregistered.

## Verify without a GPU

From the repository root:

```bash
python scripts/build_vireo_views.py
python scripts/audit_vireo_evidence.py
python -m unittest discover -s tests -v
```

The independent standard-library audit reconstructs all 116 condition-by-judge
means/reductions and the primary random-control contrasts from raw judgments,
checks forecast hashes and time ordering, recomputes saved forecast errors,
and verifies every imported file against its source hash. It does not substitute
for rerunning a judge or testing generalization to new organisms.

To recompute bootstrap intervals and gates, use a scratch copy of this directory
(the original analysis writes outputs). Install NumPy 2.2.6, SciPy 1.15.3, and
PyTorch 2.8.0, then set `VIREO_WORK` to the absolute scratch `auditing` directory:

```bash
export VIREO_WORK="/absolute/scratch/vireo/auditing"
export PYTHONPATH="$VIREO_WORK/src"
python "$VIREO_WORK/src/analyze.py"
python "$VIREO_WORK/initial_confirmation/analyze.py"
```

Three compact `.pt` files needed for the initial-answer monitor analysis are
included; load them with `torch.load(..., weights_only=True)`, as the scientific
source does. The much larger activation/lens caches are excluded. Native
reference logit fixtures are included once under `auditing/reference`.
Elicitation analysis uses `elicitation/src/analyze.py` and
`elicitation/src/bridge_sensitivity.py`, with NumPy/SciPy, from a scratch copy.

## Inference replay

Model identities and exact revisions are in `auditing/configs/assets.json`.
Scientific code is preserved rather than silently ported: `VIREO_WORK`,
`PYTHONPATH`, and the documented study-era absolute paths must be adapted to a
new host. Do not run prompt generators or freeze scripts over the released
evidence. No command above provisions compute or performs paid inference.

The full CUDA environment is recorded in `auditing/logs/environment.txt`.
Core dependencies were torch 2.8.0, transformers 4.55.4, accelerate 1.10.1,
huggingface_hub 0.34.4, safetensors 0.6.2, numpy 2.2.6, scipy 1.15.3,
scikit-learn 1.7.2, and matplotlib 3.10.6. Native reference/training uses
MLX 0.32.2 and MLX-LM 0.31.3 with CUDA; this is not a claim of historical Metal
runtime equivalence. Jacobian computation uses the upstream `jacobian-lens`
checkout at `581d398613e5602a5af361e1c34d3a92ea82ba8e`, identified in
`auditing/reference/initial_source_manifest.json`.

The execution order is source-asset acquisition, native validation, neutral
training or restoration, conversations and history construction, representation
extraction, lens fitting, readout/direction fitting, forecast freezing,
interventions, blinded judging, and analysis. Initial-answer execution uses
`initial_confirmation/run.py` and the original fitted advisory lenses; it
requires the large intermediate states regenerated by the preceding code.
The released `acquire.py` downloads base/judge assets; the public Vireo adapter
must additionally be obtained at the pinned revision and placed in the path
documented by `modeling.py`. Supply the trained neutral adapter at
`data/clean/adapters.safetensors`. The training code and exact inputs are under
`neutral_training`; its recorded `/work`, `/cache`, and `/results` paths need
mounts or explicit porting on another host.
